# ЧебурNET Traffic Control

Независимый менеджер списков блокировки IPv4/IPv6 для входящего трафика Linux-сервера.

**0.1.0-alpha.5 — экспериментальная версия. Только отдельная тестовая VPS с доступом к консоли провайдера.**
Полный цикл на VPS, реальная блокировка пакетов, перезагрузка и совместимость с UFW ещё не подтверждены.
Это не стабильный релиз 1.0 и не замена TrafficGuard на рабочих нодах.

Автор: **Леонид Копысов** · [GitHub](https://github.com/leonidkopysov) · [Telegram](https://t.me/kopysovleonid).

## Возможности

- Один самостоятельный Python-скрипт, без скачивания или запуска стороннего исполняемого кода.
- Три внешних списка включены: antiscanner, government_networks, skipa.
- Собственная таблица `inet cheburnet_tc`; общие правила firewall не очищаются.
- IPv4/IPv6, ручные баны и исключения отдельных IP.
- Обновление целиком: при недоступности или ошибке хотя бы одного источника старые списки сохраняются.
- Проверка синтаксиса nftables перед атомарным применением.
- Первое включение с отключением через 120 секунд без подтверждения.
- Восстановление из локальной копии при загрузке; обновление раз в сутки после подтверждения.
- Цветное главное меню: все действия расположены вертикально, опасные операции выделены отдельно.
- До установки главное меню предлагает установку; запуск меню от обычного пользователя блокируется заранее.
- Проверка зависимостей: отсутствующие `nftables` и `ca-certificates` автоматически устанавливаются через apt.
- Необязательный журнал ядра с ограничением частоты записей; точные счётчики пакетов в текущей таблице.

## Границы защиты

Фильтруется только INPUT: сервер и Docker `network_mode: host`. Docker bridge и транзитный трафик НЕ защищаются.
SSH-порты, loopback, существующие/связанные соединения и разрешённые IP исключаются из нашей блокировки.
**IP из внешних списков не блокируются на настроенных SSH-портах.** Это осознанный приоритет сохранения
административного доступа: подбор паролей SSH должны ограничивать ключевая авторизация, Fail2ban и firewall.
Это не открывает их в UFW: другие таблицы firewall по-прежнему могут отклонить пакет.
Существующие соединения не разрываются при добавлении бана. Проверяйте блокировку новым подключением.

Это фильтр по репутационным спискам, не детектор сканирования, не защита канала от DDoS.
Адрес из government_networks не обязательно является сканером. Возможны ложные блокировки.
Счётчики сбрасываются при пересоздании таблицы/перезагрузке; ограниченные логи не равны полной статистике.
В главном меню есть топ-10 IP по записям блокировок за 24 часа (последние 10 000 записей).
RDAP показывает организацию-регистранта или имя сети, но не доказывает личность отправителя.
Docker bridge пока не реализован.

## Установка на тестовой VPS

Требуются root, Python 3.10+ и работающий systemd. Целевые ОС: Ubuntu 22.04/24.04, Debian 12/13;
это целевая совместимость, а не перечень уже протестированных систем.
При `install` скрипт проверяет `nftables` и `ca-certificates`. Если они отсутствуют, выполняются
`apt-get update` и неинтерактивная установка только недостающих пакетов. Служба nftables не включается,
существующий ruleset не очищается. Автоустановка поддерживается только на Ubuntu/Debian с `apt-get`;
установка Python и запуск systemd автоматически невозможны, поэтому они проверяются отдельно.
Если после установки пакеты не обнаружены, работа останавливается до изменения firewall.
Существующий TrafficGuard требуется сначала штатно удалить. Автоматическая миграция отсутствует.

Скачайте файл `cheburnet-traffic-control.py` и `SHA256SUMS` из этого репозитория в один каталог.
Просмотрите исходник и проверьте `sha256sum -c SHA256SUMS`. Контрольная сумма не заменяет подпись и доверие источнику.

Интерактивная установка с подтверждением определённых адресов. Значение `SSH_CONNECTION` передаётся
через `env`, потому что стандартная политика `sudo` в Ubuntu/Debian обычно удаляет его из окружения:

```bash
sudo env SSH_CONNECTION="${SSH_CONNECTION:-}" python3 ./cheburnet-traffic-control.py install
```

IP администратора и SSH-порт предлагаются из `SSH_CONNECTION`, каждый — с подтверждением Д/Н.
При Н введите своё значение; отклонённый адрес/порт не добавляется в исключения.
Без SSH_CONNECTION (например, в консоли провайдера или после sudo) значения запрашиваются вручную.
IP может принадлежать VPN/NAT/промежуточному серверу, а не вашему устройству.

На нодах, установленных CheburNET Vision Installer, исходящие IP панели предлагаются из поля `panel_ips`
в `/opt/remnanode/settings.json`, если файл
принадлежит root, не является ссылкой и недоступен для записи группе/остальным. Секреты не выводятся,
конфигурация Vision не изменяется. Без подходящих настроек запросим IP или домен панели.
DNS-адреса домена требуют отдельного подтверждения: CDN и исходящий IP панели могут различаться.
Перед записью выводится итог и запрашивается согласие. Фильтрация остаётся выключенной до activate.

Для автоматизированной установки можно явно задать все параметры (без вопросов и без добавления
адресов из SSH_CONNECTION). Замените примерные IP и порт на реальные:

```bash
sudo python3 ./cheburnet-traffic-control.py install \
  --ssh-port 22 --allow 198.51.100.10 --allow 198.51.100.20
sudo cheburnet-traffic-control activate
```

Откройте **новое** SSH-подключение и проверьте связь панели с нодой, затем в течение 120 секунд:

```bash
sudo cheburnet-traffic-control confirm
sudo cheburnet-traffic-control status
```

Без confirm таблица удаляется таймером. После disable нужно заново activate → confirm.
Откат не является абсолютной гарантией доступа: держите открытой консоль провайдера.

## Управление

Главное меню: `sudo cheburnet-traffic-control`. Топ обновляется при возвращении в меню.
Цвета автоматически отключаются при перенаправлении вывода или при переменной `NO_COLOR`.
Расшифровка передаёт IP из топа внешнему rdap.org и реестру адресов, только по запросу меню/top;
холодные запросы выполняются параллельно, результат кэшируется на 7 дней.
Без внешних запросов: `sudo cheburnet-traffic-control top --no-resolve`.

```bash
sudo cheburnet-traffic-control update
sudo cheburnet-traffic-control ban 203.0.113.0/24
sudo cheburnet-traffic-control unban 203.0.113.0/24
sudo cheburnet-traffic-control allow 203.0.113.7
sudo cheburnet-traffic-control disallow 203.0.113.7
sudo cheburnet-traffic-control disable
sudo cheburnet-traffic-control uninstall --yes
```

unban удаляет только точную запись ручного списка. Если адрес остаётся во внешнем списке или другом ручном CIDR,
блокировка сохраняется; используйте allow IP. Исключения имеют приоритет над банами.
Удаление сохраняет `/var/lib/cheburnet-traffic-control/state.json`; автоматическая переустановка поверх него запрещена.

Логирование включено по умолчанию; при установке `--no-logging` отключает его и сбор топа:

```bash
journalctl -k --grep='CBTC[46] '
journalctl -u cheburnet-traffic-control-update.service
systemctl status cheburnet-traffic-control-update.timer
```

Нет обещания нулевого расхода диска: срок хранения журнала задаётся системным journald.
Перезагрузка/очистка firewall сторонними программами может удалить нашу таблицу; `status` покажет её отсутствие,
`restore` восстановит её, если компонент подтверждён. Watchdog пока отсутствует.

## Проверки

```bash
python3 -m unittest discover -s tests -v
python3 -m py_compile cheburnet-traffic-control.py
```

Перед production обязательны тесты в отдельной VM: install/activate/timeout/confirm/disable/uninstall,
IPv4/IPv6, новые подключения, UFW reload, перезагрузка, отказ каждого списка, ручные исключения и сбой записи.
Unit-тесты не подтверждают работу firewall в ядре.
